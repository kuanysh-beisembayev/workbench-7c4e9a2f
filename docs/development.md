# Разработка и публикация

Все команды выполняются из корня репозитория.

## Запуск

Используйте Node.js 24.19.x и pnpm 11.25.0. Допустимый диапазон Node указан в `package.json`.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Используйте адрес, который выводит Vite. Для фиксированного порта:

```sh
pnpm dev --port 4173
```

Установка пакетов должна использовать Socket из `.npmrc`. Не заменяйте реестр публичным для обхода ошибки или блокировки. Сохраняйте точные версии и lockfile.

Не добавляйте секреты в код или публичные файлы. `.env` и файлы ключей исключены из Git.

## Проверки

| Команда | Результат |
| --- | --- |
| `pnpm test` | Проверяет поведение движка, схемы и покрытие данных. |
| `pnpm validate:data` | Проверяет JSON и портреты; обновляет `statistics.schema.json`. |
| `pnpm run audit` | Запрашивает OSV для пакетов из lockfile. Нужен доступ к сети. |
| `pnpm build` | Проверяет TypeScript в `src/`, данные и создаёт `dist/`. |
| `pnpm preview` | Запускает локальный просмотр готовой сборки. |

Проверка типов сейчас охватывает `src/`. Скрипты и тесты запускаются Node с удалением аннотаций типов, но не входят в `tsconfig.json`.

Для изменения движка добавляйте проверки поведения, которое должно измениться. Не подгоняйте ожидаемые результаты под конкретные имена героев.

Для изменения только документации достаточно проверки ссылок, путей и соответствия коду. Публиковать сайт для такой правки не требуется.

## Ручная проверка интерфейса

Проверьте следующие сценарии после изменения интерфейса или движка:

1. Откройте пустой драфт. Проверьте рекомендации для всех позиций.
2. Добавьте Phantom Lancer противнику. Проверьте изменение списка carry.
3. Замените его на Doom. Проверьте пересчёт рекомендаций.
4. Добавьте союзников в разные позиции и несколько банов. Проверьте исключение занятых героев.
5. Откройте поиск. Проверьте начальный фокус, поиск по сокращению и выбор клавишей Enter.
6. Перезагрузите страницу. Проверьте восстановление драфта.
7. Нажмите New draft. Проверьте очистку слотов и банов.
8. Проверьте ширины 320, 390 и 1280 px. На телефоне должен отображаться один таб рекомендаций.
9. Проверьте отсутствие горизонтального скролла и обрезки портретов.

Этот список — ручная проверка. Автоматических браузерных тестов в репозитории пока нет.

## Обновление статистики

Формат и формула описаны в [data.md](data.md). Не меняйте знак Advantage без проверки исходного заголовка таблицы.

Для сохранённого экспорта Dotabuff:

```sh
node --experimental-strip-types scripts/import-dotabuff.ts data-sources/dotabuff-week-2026-10-15.json
pnpm validate:data
pnpm test
```

Импорт заменяет `matchups`, но сохраняет существующие `roleStats`. Он не загружает свежие страницы и не обновляет данные ролей.

Текущий импорт содержит дату и описание источника ролей от 2026-10-15 в коде. При следующем обновлении проверьте эти поля отдельно.

`updatedAt` после импорта берётся из экспорта Dotabuff. Это не подтверждение свежести сохранённых данных ролей.

Данные ролей обновляются вручную в `statistics.json`. Отдельного импортера Dota2ProTracker пока нет. Укажите реальные период, патч и состав выборки в метаданных.

Сохраняйте исходный экспорт отдельно. Не обозначайте статистику как ranked-only или относящуюся к определённому рангу без подтверждения источника.

## Добавление героя

Добавьте уникальный ID, имя, slug, псевдонимы и проверенные теги в `heroes.json`. Добавьте PNG в `public/images/heroes/<slug>.png`.

Проверка требует PNG размером минимум 128×72 и пропорции 16:9. Дополните статистику ролей и матчапов.

Импортер Dotabuff требует полную матрицу для текущего каталога. Старый экспорт перестанет подходить после добавления героя.

## Публикация

Исходники находятся в `main`. Готовый сайт находится в `gh-pages`. GitHub Pages публикует корень `gh-pages`.

Требуются Git и GitHub CLI с доступом к существующему репозиторию. Проверьте авторизацию:

```sh
gh auth status
```

Сохраните нужные файлы коммитом и отправьте `main`. Затем выполните:

```sh
pnpm deploy
```

Команда запускает тесты, аудит и сборку. Затем она публикует `dist/` в `gh-pages`. Она не отправляет изменения исходников в `main`.

Проверить публикацию:

```sh
gh run list --repo kuanysh-beisembayev/workbench-7c4e9a2f --limit 3
```

Дождитесь успешного выполнения `pages-build-deployment`. Затем откройте [приложение](https://kuanysh-beisembayev.github.io/workbench-7c4e9a2f/) и проверьте изменение.

Для отката верните нужное состояние исходников и данных отдельным коммитом. Затем повторите проверку и публикацию.

## Частые ошибки

| Симптом | Что проверить |
| --- | --- |
| Нет рекомендаций | `isDemo`, число матчей роли, покрытие выбранных врагов и сообщение загрузки JSON. |
| Список кажется неверным | Компоненты `Recommendation`, знак Advantage, периоды и состав выборок. |
| Не видна новая версия | Статус Pages, опубликованную ветку, ресурсы сборки и повторную загрузку страницы. |
| Не загружается портрет | Наличие файла, соответствие slug и адрес относительно базы приложения. |
| Портрет стал квадратным | Последующие CSS-правила и мобильные media queries. В файле есть переопределения. |
| Не восстанавливается драфт | Версию и структуру localStorage, известные ID и настройки хранения браузера. |
| Git просит учётные данные | Авторизацию `gh` и настройку credential helper. Не вставляйте токен в URL репозитория. |
| Аудит завершился ошибкой сети | Доступ к OSV. Ошибка сети не означает отсутствие уязвимостей. |
