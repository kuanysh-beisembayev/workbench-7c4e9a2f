# Состояние и дальнейшая работа

Состояние зафиксировано 2026-10-15 после коммита `c9b5b97`. Пункты ниже описывают планы, а не готовые возможности.

## Что работает

- Ввод союзников, противников и банов.
- До пяти рекомендаций для каждой из пяти позиций.
- Табы позиций на телефоне и автоматический фокус поиска.
- Локальные портреты 127 героев без квадратной обрезки.
- Сохранение драфта в браузере и перенос старого формата.
- 266 записей статистики ролей и полная матрица из 16 002 направленных записей противников.
- Скорректированный Advantage Dotabuff вместо прежнего сравнения несовместимых обычных винрейтов.
- Учёт малой выборки, плохих матчапов, доступных контрпиков и недостающих способностей команды.
- Публикация на GitHub Pages.

На момент фиксации прошли 25 автоматических проверок. Одна проверка перебирает 100 воспроизводимых драфтов с банами для всех позиций.

Эти проверки подтверждают корректность поведения. Они не подтверждают прирост винрейта.

## Известные ограничения

Данные ролей и матчапов относятся к разным выборкам. Ролевая статистика получена из игр 7000+ MMR. Сегментация Dotabuff по рангу и роли не подтверждена.

Фильтр Dotabuff «This Week» не подтверждает единый патч или только рейтинговые матчи. Автоматического обновления и предупреждения об устаревших данных нет.

В текущем JSON нет статистической синергии союзников. Союзники влияют через состав команды и доступность героев. Формат поддерживает будущие скорректированные союзные пары.

Теги способностей содержат только четыре категории. Они не моделируют линии, тип урона, темп игры или взаимодействие конкретных способностей.

Риск контрпика использует частоту героев как приближение. Он не моделирует реальные ответы противника или доступные ему позиции.

Веса и пороги заданы вручную. Нет обученной модели, проверки на отложенных матчах или вероятности победы.

## Ближайший этап: проверка качества

Сначала создайте отдельный набор реальных матчей для оценки. Зафиксируйте источник, патч, дату, режим, ранг и надёжность определения позиций.

Для проверки промежуточного драфта используйте только информацию, доступную в тот момент. Не передавайте движку будущие пики или результат матча.

Разделяйте данные по времени. Удаляйте повторные матчи. Статистика из проверяемого периода не должна попадать в исходные оценки движка.

Сравните текущий движок с простой рекомендацией по силе героя на роли. Измерьте покрытие, устойчивость результатов и влияние каждого компонента.

Наблюдаемый результат матча не показывает, что случилось бы с другим героем. Не называйте такое сравнение доказательством причинного эффекта рекомендации.

**Готовность этапа:** набор данных воспроизводим, метод оценки описан, ограничения указаны, результаты сравнения сохранены в репозитории.

## Следующий этап: качество данных

- Добавить воспроизводимый импорт статистики ролей. Сохранять дату каждого источника отдельно.
- Проверить совместимость периодов, патчей и составов выборок.
- Получить совместимые скорректированные данные союзных пар с известными позициями.
- Добавить отчёт о пропусках, расхождениях источников и изменениях после обновления.
- Проверить реакцию приложения на новый патч и неполный каталог.

**Готовность этапа:** обновление данных воспроизводится из сохранённых источников и не создаёт ложных метаданных.

После этого настройте веса на обучающем периоде. Проверьте результат на другом периоде. Меняйте веса только при измеримом результате.

## Последующая разработка

Добавьте автоматические проверки мобильного интерфейса, поиска, фокуса, сохранения драфта и загрузки изображений.

При необходимости упростите структуру `App.tsx` и CSS. Сначала зафиксируйте текущее поведение. Не совмещайте рефакторинг с изменением формулы без отдельных проверок.

Автоматическое обновление данных потребует отдельного решения об источниках и способе запуска. Текущий MVP остаётся статическим сайтом с ручным обновлением JSON.

## Отложенные идеи пользователя

**Пул героев.** Позже можно ограничивать рекомендации героями, которых пользователь готов играть. Сейчас такого фильтра нет.

**Обратная связь после матча.** Позже можно запрашивать результат, фактическую роль и статистику. Сам факт сбора обратной связи не обучает движок.

Перед персонализацией потребуется определить хранение, согласие пользователя, удаление данных и метод оценки качества. Выбор базы данных пока не сделан.

## Что сохранять при дальнейшей работе

Сохраняйте рекомендации для всех позиций без начального выбора роли и ранга. Приоритет — использование с телефона во время драфта.

Сохраняйте минимальный интерфейс. Не добавляйте числовой fit, кнопку Pick, блок Why this hero или вводные пояснения без нового запроса пользователя.

Данные должны оставаться файлами репозитория в рамках текущего MVP. Не добавляйте кнопку загрузки примерных данных.

После изменения алгоритма обновляйте [data.md](data.md), проверки и описание ограничений. После изменения продукта обновляйте [обзор](README.md).
